# AGENTS.md

## Scope

- This repo is a Nix flake for machine and Home Manager configuration, not an application codebase.
- Start with `flake.nix` and `modules/flake/`; they define the real wiring.
- The flake only declares `x86_64-linux`.

## Entry Points

- `flake.nix` contains inputs and the minimal flake-parts/import-tree bootstrap.
- The public outputs are `nixosConfigurations.{laptop,gamer,work}`, `packages.x86_64-linux.flate`, and the treefmt check/formatter.
- `modules/flake/hosts.nix` wires embedded Home Manager into every host for user `stianrs`.
- Each host lives in one file, `modules/hosts/<hostname>.nix`: its metadata and its host bundle. The host bundle merges into `internal.nixosModules.<hostname>` and sets the host's home configuration through `home-manager.users.stianrs`.
- `work` is the WSL host: its host bundle sets `wsl.enable`. Every host imports the nixos-wsl module, which stays inert until that option is set.

## Module Layout

- Every maintained `.nix` file under `modules/` is an automatically imported flake-parts module.
- Underscore-prefixed path segments are ignored by `import-tree` and hold generated hardware, package recipes/sources, assets, or application configuration.
- Reusable NixOS behavior merges into `internal.nixosModules.default`; host-only behavior merges into `.<hostname>`. WSL-only behavior merges into `.default` under `lib.mkIf config.wsl.enable`, which is the only test for a WSL host.
- Reusable Home Manager behavior merges into `internal.homeModules.default`.
- A module lives under the tree whose options select it. A NixOS module may set Home Manager configuration through `home-manager.users.stianrs` or by contributing to a Home Manager bundle.
- Desktop session Home Manager behavior merges into `internal.homeModules.desktop`. `modules/nixos/desktop.nix` imports that bundle only when NixOS `modules.desktop.enable` is set, so its modules carry no desktop guard. A host bundle puts its desktop session lines under one `lib.mkIf config.modules.desktop.enable`.
- A desktop app's module owns its Hyprland autostart (its own `hl.on("hyprland.start", ...)`) and window rules as self-contained `extraConfig` fragments that declare and read no Lua locals. Keybindings stay in `modules/home/desktop/noctalia/keys.nix`, and only `noctalia/hyprland.nix` enables Hyprland.
- Domain terms (host, bundle, desktop session, desktop app) are defined in `GLOSSARY.md`; use them in code, comments and docs.
- `modules.*` holds only the options a host bundle selects: NixOS `desktop.enable` and `services.tailscale.enable`, and Home Manager `kubernetes.enable`. Every other module applies unconditionally in its bundle. Declare a new option only when hosts need different values, and test it where its behavior lives rather than mirroring it into Home Manager.

## Packages

- `modules/flake/nixpkgs.nix` composes package additions, stable aliases, and `pkgs.unstable` in that order.
- Add a package recipe under `modules/packages/_recipes/`, register it with `internal.packageRecipes`, and export the overlay package from a module under `modules/packages/`.
- `modules/packages/_sources/generated.nix` is generated by nvfetcher; edit `modules/packages/nvfetcher.toml` instead.

## Verification

- Inspect current outputs with `nix flake show --all-systems`.
- For host changes, prefer building the exact target locally: `nix build .#nixosConfigurations.<host>.config.system.build.toplevel`.
- For exported packages, prefer building the exact package locally: `nix build .#flate`.
- CI uses `nix flake check` as a general flake validation step and also builds all exported `nixosConfigurations` and `packages.x86_64-linux` outputs through the cache-building workflow.
- When updating `modules/packages/nvfetcher.toml` or generated sources, regenerate with the locked nvfetcher and require no diff under `modules/packages/_sources`.
- Workflow changes are linted with `nix shell --inputs-from . nixpkgs#actionlint --command actionlint .github/workflows/*.yaml`.
- Renovate configuration changes are validated with `nix shell --inputs-from . nixpkgs#renovate --command renovate-config-validator --strict --no-global .renovaterc.json5`.

## Local Rebuild

- On machines that already use this repo, `programs.nh.flake` is pinned to `/home/stianrs/nix` in `modules/nixos/system/nh.nix`.
- For local rebuilds on those machines, prefer `nh os switch`.

## Generated And Secrets

- Secrets are handled with `opnix`.
- To refresh nvfetcher-managed sources, run from `modules/packages/`: `nix-shell -p nvfetcher --command 'nvfetcher -l /tmp/nvfetcher-changes --keep-old'`.
